全景：信令在外，栈在里

十分钟搞清 rustrtc 管什么、不管什么，以及浏览器和 SIP 怎么共用一套 PeerConnection。

1. 信令不在这个栈里

rustrtc 会生成和解析 SDP，并维护本地的 SignalingState（src/peer_connection.rs:6883@e13b5f2）。它不会把这段 SDP 送到对端。

交换 SDP 是应用的事：

  • 和浏览器：示例用本地 HTTP POST /offer（examples/datachannel_chat.rs、examples/echo_server.rs 都听 127.0.0.1:3000）。
  • 和 SIP 通话：由 rsipstack 把 SDP 放进 INVITE / 200 OK 的 body 里传来传去。rustrtc 只收发 RTP/SRTP 媒体。

典型顺序（README Usage）：PeerConnection::new → create_offer / create_answer → set_local_description →（应用把 SDP 发出去）→ set_remote_description。全 ICE 时还要 wait_for_gathering_complete，再取带候选的完整 SDP。协议：RFC 3264 §3 Offer/Answer 模型；生成规则见 §5 / §6。

3. 一套 API，两种对端

PeerConnection（src/peer_connection.rs:699@e13b5f2）吃一份 RtcConfiguration（src/config.rs:602）。配置里两个正交字段决定媒体怎么走：

  • Connectivity（src/config.rs:149）：路怎么找。变体是 Sdp（用对端 SDP 的 c=/m= 地址，可加 latching）、IceLite（RFC 8445 §2.5，应答检查、跟随提名）、Ice（完整采集与提名）。
  • Keying（src/config.rs:171）：密钥怎么换。变体是 None（明文 RTP / RTP/AVP）、Sdes（a=crypto，RFC 4568）、Dtls（指纹 + DTLS-SRTP，RFC 5763/5764）。

任意 Connectivity 可以配任意 Keying。注释写明：数据通道（SCTP）需要 Dtls（src/config.rs:167–169）。

不要从「默认值」起步，从对端种类起步（RtcConfiguration::webrtc :967，::sip :981）：

预设ConnectivityKeying还改了什么
webrtc()，对浏览器 / SFUIceDtlswebrtc_extensions = true，rtcp_mux_policy = Require，bundle_policy = MaxBundle
sip()，对 SIP 中继 / 话机SdpNone扩展关掉，Negotiate（许多 SIP 对端不 mux RTCP），Balanced

常见改法：SIP 要 SDES-SRTP，就 sip() 再把 keying = Keying::Sdes；像 Linphone 这种带 ICE 的话机，再把 connectivity = Connectivity::IceLite。出处：README Configuration 段，以及上面两个构造函数的文档注释。
