读音频 SDP：m=audio、c=、a=rtpmap

本课只学会读三类行：媒体行、连接地址、编码映射。下面是虚构、删减的 SDP 教学片段，不是真实抓包，也不是完整可直接建立连接的 SDP。

m=audio 9 UDP/TLS/RTP/SAVPF 111 0
c=IN IP4 0.0.0.0
a=rtpmap:111 opus/48000/2
a=rtpmap:0 PCMU/8000

1. m=audio：这是什么媒体，编号是什么

格式：m=<媒体> <端口> <协议> <格式列表>。

  • audio：音频。
  • 9：端口字段。这个 ICE 场景里是占位端口，不是最终音频目的端口。
  • UDP/TLS/RTP/SAVPF：传输协议标识；这里描述 WebRTC 常见的 DTLS-SRTP 音频。不要从中误读出“每个音频包都装进 DTLS”。
  • 111 0：这段 RTP 媒体的 payload type（PT）列表，是负载类型编号，不是额外的端口。

依据：RFC 8866 §5.14。

2. c=：连接地址；与端口分开看

c=IN IP4 0.0.0.0 中，IN 表示 Internet，IP4 表示 IPv4，最后是连接地址。媒体级 c= 可以覆盖会话级 c=。RFC 8866 §5.7

本例的 0.0.0.0 是地址占位，m= 里的 9 是端口占位，不是同一个字段。ICE 会检查候选并最终选路，不是把音频发到 0.0.0.0:9。这是 ICE 场景里的含义，不要把所有 SDP 中的 0.0.0.0 都机械理解成同一件事。RFC 8839 §4.3.1

对比：不使用 ICE 的普通 RTP，若片段为 m=audio 40000 RTP/AVP 0 与 c=IN IP4 198.51.100.20，通常就是向 198.51.100.20:40000 发 RTP。这里的地址同样只是文档示例。

3. a=rtpmap：用 PT 找编码

格式：a=rtpmap:<PT> <编码名>/<RTP时钟率>[/<声道参数>]。

  • 111 opus/48000/2：PT 111 对应 Opus；48000 是 RTP 时间戳时钟率，不是码率，也不直接证明麦克风采样率；/2 是声道参数。
  • 对 Opus，SDP 按规范必须写 opus/48000/2，即使这时实际发送的是单声道，因此不能只凭 /2 断定正在发送立体声。
  • 0 PCMU/8000：PT 0 对应 PCMU，RTP 时钟率 8000 Hz。普通音频 rtpmap 省略声道数通常表示 1。

111 这个动态 PT 不是 Opus 永久固定的编号，要看本次 SDP 的映射。依据：RFC 8866 §6.6、RFC 7587 §7。

只记一句

m= 看媒体、端口、协议和 PT 列表；c= 看地址；rtpmap 把 PT 解释成编码和 RTP 时钟率。
